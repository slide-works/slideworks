What SW-1 looks like when it lands

An agent builds a deck through MCP from ready-made blocks. A person opens it by URL, shares it, and presents it in the browser on a laptop or a phone. The mockups cover the five screens SW-1 ships, the default slide blocks, and the agent's side of the MCP session. Six questions at the end need your call before planning.

In SW-1, and what waits for later Features

Purple marks a later Feature. The mockups show those spots as disabled controls so you can see where each one plugs in.

SW-1Ships in the foundation

  • Decks library: create, open by URL, presenter accounts
  • Deck page: slide grid, notes, link, who changed what
  • Sharing: private, anyone with the link, or named viewers
  • Player: scaled 1920×1080 canvas, keys, click, swipe, steps, #slide.step links, previous/next, progress, fullscreen
  • 17 building blocks in one neutral default theme
  • MCP server: create a deck, add, update, move and delete slides, notes, images, sharing, list layouts, get the URL

  • SW-2 theme picker and more templates
  • SW-3 "Check slides": screenshots, overflow and contrast lint
  • SW-14 anchored comments, notes to the agent, versions
  • SW-4 presenter window, overview grid, PDF
  • SW-5+ audience join, polls, phone remote
  • SW-13 editing in the browser

Player

live: use the buttons or ← → when focused

One canvas size for every screen. The 1920×1080 slide scales evenly to fit and never reflows. A phone gets the same slide, just smaller. Steps reveal one item at a time, and the address bar carries #slide.step.

Player acceptance rules

  • A deep link opens on load. A bad number falls back to slide 1.
  • replaceState on each move, and Back/Forward still work
  • Each action moves exactly one slide, with no smooth-scroll and snap race
  • Keys are left alone inside inputs, editable text and IME
  • Every slide stays in the page, so comment anchors work later
  • Reduced motion turns off the slide and step transitions

The building blocks, as the sample deck

16 slides · 17 blocks

This is the deck the agent builds in section 06, one slide per layout. It ports the look of an existing hand-built HTML deck, without its branding: a light page with cards for content slides, dark slides only for the title, dividers and close, one sentence for each headline, and the part tracker at the top. Under each slide are the layout name and the slots an agent fills.

06

The agent's side: one session over MCP

The agent writes no HTML. It reads the layout catalogue, then sends each slide as a layout and its slots. The server checks every slot against its schema and rejects a slide it can't render, with the field that broke.

# brief: "20-min offsite talk on shipping smaller, 16 slides"
→ list_layouts()
← 17 layouts: title, divider, bullets, big-number, gantt, quote,
  practice, compare, two-column, table, chart, numbered-cards,
  rules, cards, close …  (each with its slot schema)

→ create_deck({ title: "Ship smaller", author: "Sam Rivera",
    parts: ["The cost", "Slice it", "Ship it", "Make it stick"] })
← deck 7Kq2 · private · /d/7Kq2/ship-smaller

→ add_slide({ deck: "7Kq2", layout: "practice", part: 2,
    kicker: "Slice it",
    headline: "Slice by what a customer can do, not by layer",
    do: [{ lead: "Start from one user action", text: "…" }, …],
    comes_back: ["Feedback in days, not quarters.", …],
    avoid: ["\"API first, UI later.\" …"],
    callout: { tone: "bad", text: "If a slice can't be demoed…" },
    notes: "Say: ask the room for last month's biggest story…" })
← slide 8 · steps 0 · /d/7Kq2#8

→ upload_image({ deck: "7Kq2", name: "story-map.png" })
← upload URL (10 min) · then image: "img_3f9" in a slot

→ add_slide({ layout: "bullets", reveal: "one-by-one", … })
← slide 3 · steps 4

→ set_sharing({ deck: "7Kq2", level: "link" })
← sharing: link · logged to activity

→ get_deck_url({ deck: "7Kq2", slide: 1 })
← https://slideworks.example/d/7Kq2/ship-smaller#1

Questions for you

6 answered · D3–D8 on SW-1

Answered 2026-11-16 and recorded on SW-1 as D3–D8. Q4 went against my recommendation: agents get full sharing control (D6). The sharing dialog, activity list and MCP tools above now show set_sharing. The forms still work if you want to change an answer.

Q1 · How does an agent describe a slide?

This is the MCP contract, and the hardest one to change after launch.

Not queued

Q2 · The default look before SW-2 adds themes

SW-1 ships one theme. It is what every early deck looks like.

Not queued

Q3 · Do the part tracker and footer come with SW-1?

The catalogue put this chrome under SW-2 (templates). But the dividers' journey timeline needs the same parts list.

Not queued

Q4 · Can an agent change who sees a deck?

If it can, a prompt injection could make a private deck public. Your answer: full control (D6).

Not queued

Q5 · Does the deck page show the agent's activity in SW-1?

It answers "what did the agent just do?". SW-14's versions would use the same change log.

Not queued

Q6 · Are any blocks missing from SW-1, or in it when they shouldn't be?

Uncheck any block to move it to SW-2. Chart and gantt cost the most to build.

Not queued
