Rules

  • The same block everywhere: {tone, fill?, text ≤ 160, reveal?}. One callout per slide.
  • It sits last in .sw-body, full width, 30 px under the content. Cards, panels, images and charts shrink to the height left; text layouts are checked by SlideFit with the callout's height added (124 px for one line, 162 px for two).
  • A slide with no callout is checked exactly as today, so no stored slide changes.
  • callout.reveal: "last" makes the callout the slide's last step (section 04). Left out, it shows with the slide, as bullets does today.
  • Not added to quote, title, divider, close, join, poll, qa or practice (which has one).
  • Group B's layouts add it with one line in the catalogue: Opt("callout", new BlockSlot(Callout)) and <BodyCallout> in the component.

Slot text stays plain text. A separate emphasis slot names a phrase that is already in the text and gives it a tone. The server checks the phrase is there exactly once. Nothing is parsed, so a length limit and the fit check see the same text as before.

// refused, each naming the entry
quote.emphasis[0].text: "mass unemployed" is not in quote.quote
quote.emphasis[0].text: occurs 2 times in quote.quote;
  use a longer phrase that occurs once
bullets.emphasis[1].text: overlaps emphasis[0]
big-number.emphasis[0].in: expected one of caption, headline

Rules

  • emphasis: optional list of 1–3 {text ≤ 80, tone, in?}. tone is accent, positive or negative (aliases info, good, bad).
  • Only display text of 28 px or more takes it: headline on every layout that has one, quote.quote, big-number.caption, close.headline and close.sub. Body text, cards and captions do not.
  • The phrase must be in the slot exactly once, matched character for character. Entries may not overlap.
  • The client splits the string at the phrase and wraps it in a span with data-tone. No HTML, no Markdown, no dangerouslySetInnerHTML.
  • An edit that removes the phrase from the text is refused until the entry goes too, so a slide never carries a stale entry.
  • Group B's statement and wider quote declare their slots with emphasis: ["statement", "sub"] on the layout definition and render through <Emphasised>.

Where an icon goes

  • cards.cards[].icon: 44 px, accent (the card's ink on a toned card).
  • bullets.items[].icon, two-column.left|right.items[].icon, image.points[] as {icon, text}: 40 px in the mark's place.

create_deck { title: "…", parts: [
  "Before AI",
  { name: "Spicy autocomplete", short: "Autocomplete",
    caption: "2021–22" },
  { name: "Software factory", short: "Factory",
    caption: "2026, north star" },
  { name: "Appendix", mark: "A" } ] }

parts[1].short: at most 16 characters (got 18)
parts[2]: a part with a mark must come after every numbered part
parts[3].mark: at most 2 characters (got 3)

Rules

  • name ≤ 40 (unchanged), short ≤ 16, caption ≤ 24, mark 1–2 characters. Still 8 parts at most, marked ones included.
  • Marked parts come last, so the numbers of the others do not move. A slide's part is still a 1-based index into the whole list.
  • A stored deck's parts are plain names and read as {name}: no migration.
  • No per-slide "hide tracker" switch. Three rules cover the source deck: no tracker on a slide without a part, none in an unnumbered section, and a layout can opt out (group B's statement).
  • get_deck and the play view return each part as an object with all four fields.

preview_deck: a short response for a long deck

SW-372

For 44 slides the response was about 25 KB: 44 URLs in slides, then the same 44 URLs again as 44 commands. Now there is one URL template and one loop. The 44-slide response is about 3 KB.

// today, 44 slides, about 25 KB
{ slides: [ { number: 1, render_url: "https://…/render/Rz…/1#token=eyJ…" },
            { number: 2, render_url: "https://…/render/Rz…/2#token=eyJ…" },
            … 42 more … ],
  viewport, wait_for, expires_in_seconds, player_url, share_card_url,
  instructions: "…
npx -y playwright@1.62.0 screenshot … \"https://…/1#token=eyJ…\" slide-1.png
npx -y playwright@1.62.0 screenshot … \"https://…/2#token=eyJ…\" slide-2.png
… 42 more …" }
// designed, any number of slides, about 3 KB
{ render_url: "https://…/render/Rz…/{slide}#token=eyJ…",
  slides: [1, 2, 3, …, 44],
  viewport, wait_for, expires_in_seconds, player_url, share_card_url,
  instructions: "…
3. Screenshot each slide at 1920×1080:
for n in $(seq 1 44); do
  npx -y playwright@1.62.0 screenshot --viewport-size=1920,1080 \
    --wait-for-selector='[data-ready=true], [data-error]' --timeout=60000 \
    \"https://…/render/Rz…/$n#token=eyJ…\" slide-$n.png
done
…
6. The page reads the token from the part after # when it first loads and
   then removes it from the address. A reload shows 'Render token missing':
   open the full URL again." }

With slides: [3, 7, 12] the loop is for n in 3 7 12. The instructions add a second, faster way for a long deck: a ten-line Node script that opens one browser and visits every slide. Both stay under 5 KB in total.

What groups B and C reuse

Callout

Catalogue: Opt("callout", new BlockSlot(Callout)). Rule: add LayoutRules.CalloutHeight to the body's height. Client: <BodyCallout callout step at /> as the last child of .sw-body.

Emphasis

Catalogue: emphasis: ["statement", "sub"] on the layout. The emphasis slot and its checks are added for you. Client: <Emphasised text spans /> in place of the bare string.

Icon

Catalogue: Opt("icon", new IconSlot()). Client: <Icon name size />, coloured by currentColor. Names come from src/contracts/icons.json.

Steps

Catalogue: steps: StepPlan.List("stamps"), StepPlan.Fixed(1, "the follow-up line"), chained with .Then(…); a callout step is added automatically. Client: Reveal at step, as now.
