SlideWorks · SW-944 · design mockups · 28 Nov 2026 · round 2: D4–D8 answered

Live speech V3: guests ask in their own language

A guest types a question in any catalogue language and taps Send. The server keeps what they wrote and translates it with the SW-943 engine. The guest's card then shows the sentence Sam will read. Sam, the presenter window and the big screen only ever show Sam's language. Other guests read each question in their own language, with Show original (D1). The phone, the Questions panel and the big screen are SW-9's as built; only the language parts are new. Nothing here talks into a phone: questions are typed.

01

What V3 ships

Translations epic SW-942 · blocked by SW-943 · after SW-885

In SW-944

  • The ask path takes the guest's language (SW-883's AudienceState.Language) along with the text
  • After a question is accepted, it is translated into Sam's language: the talk's subtitle language, else the deck's primary language (D2)
  • Both texts are stored: the original and its language, and every translation with the model that made it
  • The asker's own card shows "Sent to Sam as …" under what they wrote, once the translation is back
  • Sam's views (presenter window, phone remote, big screen, reports, get_questions) show Sam's language only
  • Other guests read each question in their language, with Show original per question. One translation per active guest language, the same fan-out as subtitles (D1)
  • No translation when the question is already in the reader's language. When a translation fails, the reader gets the original with a Not translated marker

Not in SW-944

  • never spoken questions. Talking into a phone in a meeting room looks like taking a call
  • D3 editing a question after seeing its translation
  • SW-943 the engine, model choice per language pair, the admin page
  • later translating names. A name is shown as typed, in every language
  • later "report a bad translation" from the phone
  • unchanged AskLimiter rate limits, review-first, hide, answered, show on screen

The guest's phone, state by state

mobile web · SW-9's Questions tab as built

The guest's language is the one they picked with the language chip (SW-883). The ask sheet doesn't add a language picker; it says, in one line, what will happen. The language stored is the one the engine detects; the chip is only a hint (D6). Upvotes, Top and New, "You", and waiting for approval all work as they do today.

Ask, reading ThaiOne new line in the sheet: Sam reads questions in English, and yours is translated after you send it. Nothing else changes: 200 characters, the name switch, no editing after sending (D3).
Just sent: translatingThe card appears at once with what Noor wrote and a "Translating for Sam…" line. Usually about a second. Her upvote counts already.
Sent to Sam as…The translation sits under the original in a violet box, so Noor can check how it reads. If it reads wrong, Withdraw takes it down everywhere and she can ask again (D7).
Already in Sam's languagePriya reads English and Sam's language is English: nothing is translated for Sam, and her card looks exactly like SW-9's.
The translation failedThe engine timed out or no model covers the pair. Noor is told Sam sees it as she wrote it, and can withdraw it. Sam sees the Thai with a Not translated marker.
Another guest, reading JapaneseEvery question in Japanese. A translated question says "Translated" and has Show original; Kenji has opened one. Questions already in Japanese have neither.
Switched language mid-sessionKenji switches to 繁中. Questions with no Traditional Chinese yet show their original with "Translating…" for a moment, then change in place. Their order doesn't move.
Review first, translatedWith review-first on, the translation still comes back to the asker straight away. Sam's To review tab gets it in English.

05

How a question gets from Noor to Sam and Kenji

The ask itself doesn't change: AskLimiter and the 201 come first, with the original text stored. Translation runs after, off the request, one call per language that someone in the room is reading. Each result is stored and then pushed to whoever reads that language.

What is stored

PollOption (question text)Unchanged: still holds the text the guest typedThe original is the record. Everything that reads it today keeps working
Question+ Language (catalogue code, not null; existing rows backfilled with the deck's primary language)The question's own language, so no reader of that language gets a translation

Answered 28 Nov, recorded as D4–D8 on SW-944. All five went as recommended. Q2 has one change: the language is a tile (a globe and a short code such as TH), not a "from ไทย" string. Q4 adds Withdraw to SW-944, because guests couldn't delete a question before. The mockups above now work this way.

Q1 → D4 · When does a new question reach someone who reads another language?

A translation takes about a second, sometimes more. Until it's back, Sam and Kenji have only the Thai.

Not queued

Q2 → D5 · Does Sam see which language a question was asked in?

The spec says Sam sees questions only in Sam's language. A tag isn't the question's text, but it is more than nothing.

Not queued

Q3 → D6 · Which language is a question in?

The guest's chip says Thai, but people often type in English anyway, or the other way round. Translating "th → en" on English text wastes a call and can mangle it.

Not queued

Q4 → D7 · D3 said "delete and ask again, as today". Guests can't delete today. What now?

The point of showing the translation is that Noor can see it reads wrong. Without a way out, all she can do is ask a second question and leave the bad one up.

Not queued

Q5 → D8 · What happens to the questions already asked when Sam's language changes?

D2 ties Sam's language to the subtitle language. Turning subtitles on, or changing their language, partway through moves it.

Not queued
