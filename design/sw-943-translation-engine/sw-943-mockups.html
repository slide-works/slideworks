What SW-943 ships

Four pieces, all on the server. Live subtitles (SW-884) and multilingual Q&A (SW-944) call the engine; they don't change here.

server config · deploy

Which models exist

  • Translation:Models in appsettings / env
  • Id, name, endpoint, adapter, languages, timeout, parallel
  • Added or removed only by a deploy
admin page · database

Which model translates what

  • Default model and pair overrides
  • Model health and latency, last hour
  • Try it, to play with the models
  • Applies to the next sentence, no restart
engine · ITranslator

One call for every feature

  • Override → default → "not translated"
  • Adapters: HyMt2 (glossary + context), TranslateGemma (text only)
  • Every call → metrics
infra · host compose

Two llama-server containers

  • Hy-MT2 1.8B Q4 (~1.1 GB RAM)
  • TranslateGemma 4B Q4 (~2.5 GB RAM)
  • CPU only, internal network, GGUF volume

States worth a look

The states that are hard to reach in the demo, shown on their own.

Adding a pair: a model that can't do it is greyed out

Cantonese ↔ English. TranslateGemma's Languages have no Cantonese, so it can't be picked, and the option says why. That's the "never used for a pair it doesn't support" rule at the point of entry.

Adding a pair that already has a row

One row per pair, both directions (D2). English ↔ Thai is the same pair as Thai ↔ English, so Add is refused and points at the existing row.

How the engine picks a model

TranslateAsync(text, from, to, context) reads the admin settings for every sentence (cached, cleared on save), so a change applies to the next one. A model is never sent a pair outside its Languages.

The orange dashed edge is D9: a single timeout goes straight to "not translated". A model the health check marks down hands its pairs to the default instead, before this flow runs.
RequestSettingsModel usedWhy
th → enThai ↔ English → TranslateGemmaTranslateGemma 4BThe override, used for en → th too. No glossary or context is sent (D5).
en → jaNo row; default Hy-MT2Hy-MT2 1.8BThe default, with the slide's SW-883 translations as a glossary and the last 2–3 sentences.
yue → enDefault TranslateGemma, no rownot translatedThe default has no Cantonese, and there is nothing to fall back to. Cantonese is added by D10.
yue → enCantonese ↔ English → Hy-MT2; default TranslateGemmaHy-MT2 1.8BThe override is what makes the pair work.
th → enThai ↔ English → typhoon-translate (removed by a deploy)Hy-MT2 1.8BThe row's model is no longer configured, so the default is used. The admin page flags the row (D12).

What runs on the prod host

D3 and D4: one llama-server container per model, internal network only, both loaded at start. Which models exist is in config, so adding a third is a compose change and a deploy, with no code change unless it needs a new adapter.

Server config appsettings.json shape

Parallel must match the container's -np. Both numbers come from llama-bench on the prod host before deploy.

{
  "Translation": {
    "DefaultModel": "hy-mt2-1.8b",   // seeds the DB once
    "Models": [
      { "Id": "hy-mt2-1.8b",
        "DisplayName": "Hy-MT2 1.8B",
        "Endpoint": "http://llm-hymt2:8080",
        "Adapter": "HyMt2",
        "Languages": ["en", "th", "ja", /* … */ "yue"],
        "TimeoutMs": 4000, "Parallel": 2 },
      { "Id": "translategemma-4b",
        "DisplayName": "TranslateGemma 4B",
        "Endpoint": "http://llm-translategemma:8080",
        "Adapter": "TranslateGemma",
        "Languages": ["en", "th", "ja", /* … */],
        "TimeoutMs": 6000, "Parallel": 1 }
    ]
  }
}

Its chat template takes the text with source and target language codes and nothing else, so the glossary and context are dropped (D5). Try it and the admin table say so with a "no glossary" tag.

Contracts the page needs (proposed)

Same pattern as /api/admin/users: one GET returns the whole view, and every change answers with the refreshed view. Overrides are soft-deleted (RemovedAt, a partial unique index on the live pair), not hard-deleted.

WhatShapeNotes
GET /api/admin/translationsTranslationAdminView { models[], defaultModelId, pairs[] }models: id, displayName, adapter, languages, glossary, health, p50Ms / p95Ms / calls over the last hour, slots busy. pairs: a, b, modelId, modelConfigured, changedLabel, changedBy.
PUT …/default{ modelId } → view400 if the model isn't configured.
PUT …/pairs/{a}/{b}{ modelId } → viewCreates or changes the row. a and b are sorted on the server, so en/th and th/en are one row. 400 if the model doesn't cover both, or a = b.
DELETE …/pairs/{a}/{b}→ viewSets RemovedAt. The pair falls back to the default.
POST …/try{ text, from, to, modelId? } → { text, modelId, via, ms, tokensIn, tokensOut, glossarySent, outcome }No modelId = resolve as live. Recorded in metrics with source=try so it can be left out of comparisons.
TablesTranslationSettings (DefaultModelId) · TranslationPairOverrides (LangA, LangB, ModelId, ChangedAt, ChangedBy, RemovedAt)EF migration. The default is seeded from Translation:DefaultModel the first time.
Metricsslideworks_translation_requests_total{model,pair,outcome,source} · slideworks_translation_seconds (histogram) · tokens_in/outPlus one Seq event per call. The admin page's hour figures come from the same counters.
